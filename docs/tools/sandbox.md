The fixed policy envelope makes sandbox selection visible:

```json
{
  "policy": {
    "sandbox": { "mode": "off" }
  }
}
```

To use the first-party implementation, install
`@mono-agent/sandbox-srt` directly and select its exact executable and settings:

```json
{
  "policy": {
    "sandbox": {
      "$use": "@mono-agent/sandbox-srt",
      "executable": {
        "path": "/absolute/private/path/to/srt",
        "sha256": "<64-lowercase-hex-characters>"
      },
      "settings": {
        "path": "/absolute/private/path/to/settings.json",
        "sha256": "<64-lowercase-hex-characters>"
      }
    }
  }
}
```

Both files must be canonical, owner-controlled, regular, single-link files.
The settings file is `0600`; the executable must be user-executable without
set-ID or group/world-write bits. The module validates device/inode identity,
mode, size, and SHA-256 content before selection and around every invocation.

## Filesystem roots for runtime processes

Core assigns each runtime instance a deterministic data root at
`<project-root>/.mono-agent/data/runtime/<instance-id>`. With a sandbox
selected, runtime-owned process artifacts stay below that canonical,
owner-private root: Claude CLI system-prompt files, Codex process working
directories and module-auth home, and OpenCode's isolated `HOME` and XDG
directories. The runtimes validate the root before the first sandboxed child
starts and clean up attempt- or process-scoped artifacts through their bounded
lifecycle. Codex's module-auth `codex-home` remains persistent instance data.

Restrictive SRT filesystem settings must name canonical absolute roots.
Relative `allowRead` or `allowWrite` entries such as `"."` resolve against the
SRT wrapper's current working directory. That directory varies across runtime
probes, protocol children, and workspace checks, so a relative rule is not a
stable workspace grant.

When a broad `denyRead` makes `allowRead` relevant, re-allow the canonical
workspace root and the exact selected runtime data roots. Also re-allow the
canonical native Claude config root (`CLAUDE_CONFIG_DIR` or its native
default) and native Codex `CODEX_HOME` when using ambient authentication.
Grant `allowWrite` only where the intended operation needs it: the canonical
workspace scope for approved workspace mutations, the Codex runtime data root
for its process and module-auth state, and the OpenCode runtime data root for
its isolated home/XDG state. If an ambient Claude or Codex client must update
native continuation state, grant the smallest required write scope in that
native config root too. Claude CLI's runtime-authored system-prompt artifact
needs data-root read access from the child; the host owns its creation and
cleanup.

With `sandbox.mode: "off"`, temporary Claude CLI prompt files, Codex process
working directories, and OpenCode isolation directories retain their direct
host behavior under the operating system temporary directory. Persistent
instance data, including Codex's module-auth home, remains under Core's runtime
data root.

Core grants the selected runtime one exact internal `sandbox.execute.v1`
executor only after capability negotiation succeeds. All four first-party
runtimes accept that grant. Pi routes all nine runtime-owned native tools
through it. The Claude CLI, Codex, and OpenCode runtimes route every
adapter-owned CLI child through it. Claude SDK mode replaces the SDK's local
Claude Code spawn with the same executor facade. With sandboxing off, those
runtimes retain their documented direct host paths. There is no
selected-sandbox fallback to those host paths.

The Claude CLI, Codex, and OpenCode configs must set `binary` to an absolute
path when a sandbox is selected. The sandbox never searches `PATH` for the
adapter entrypoint. Runtime adapters also omit operational environment values
that are unchanged from the host, so the sandbox's `environment.inherit`
selection remains authoritative. Values authored or generated by a runtime
remain per-command values and must be named in `environment.allow`; a missing
name fails before the provider child starts. In particular:

| Runtime | Selected-sandbox environment |
| --- | --- |
| Claude CLI | Inherit required operational names. Allow the configured `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`. |
| Claude SDK | Inherit required operational names. Allow `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_AGENT_SDK_VERSION`, and the configured auth name. |
| Codex | Allow the runtime-selected `CODEX_HOME` and allow `OPENAI_API_KEY` when module auth is configured. |
| OpenCode | Allow the isolated `HOME` and `XDG_*` names, process-owned `OPENCODE_*` containment/auth names, and every configured provider credential name. |

One-shot commands use an exact argument vector with `shell: false`, an empty
environment plus explicit allowlists, absolute working directories, bounded
input/output, timeouts, cancellation, process-group termination, and
idempotent stop. Long-lived runtime protocol children use the same pinned
boundary with aggregate input/output limits and bounded stop escalation.
Failure to create or retain either form fails the attempt.

Missing SRT, mismatched digests, path swaps, unsafe modes, symlinks, hard links,
overflow, timeout, or integrity drift fail closed. The package does not search
`PATH`, install SRT, generate policy, project sandbox claims onto a
provider-native runtime, or fall back to unsafe host execution.

Core rejects a selected sandbox before provider access when the chosen runtime
does not declare the exact executor capability or when its native-tool
descriptors are incompatible with the selected policy.
